# 2026.328.2101 — docs(cdi): CDI and a user volume mount work together — keep the device, drop the spec mounts

## Summary

`.agents/skills/cdi/SKILL.md` told authors that a pod with a bind mount must run as **container root** (`userns=host`, `User=0:0`) because "a CDI device cannot ride keep-id". That is both privileged and wrong.

What keep-id rejects is a CDI **spec's `mounts` section**, never the device. crun applies each CDI mount with `mount_setattr(…, MOUNT_ATTR_IDMAP, …)`, which needs `CAP_SYS_ADMIN` in the user namespace that owns the file's superblock — the initial namespace for host files — and a rootless keep-id container never holds it. Device nodes need no such mount.

The skill now states the standing rule, present tense, for the author — it makes no claim about the state of any emitter repo:

1. Run as the image user under `keep-id:uid=<uid>,gid=<gid>`; a host-owned bind or gocryptfs plaintext dir is then writable with no chown.
2. Keep the CDI device (`AddDevice=nvidia.com/gpu=all`) on every GPU unit.
3. Point the engine at a **derived devices-only spec** — `deviceNodes` kept, `mounts`/`hooks` dropped; `nvidia-ctk cdi generate` has no mounts-free mode, so the spec is a derived artifact.
4. Bind the driver libraries read-only to their SONAME paths (`libcuda.so.1`, `libnvidia-ml.so.1`, `libnvidia-ptxjitcompiler.so.1`).

Container root is a blocking defect (D-HW-10), never a legal shape.
