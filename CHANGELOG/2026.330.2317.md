# 2026.330.2317 — docs(cdi): keep-groups does not change the keep-id EPERM; the spec does

## Summary

The `cdi` skill's keep-id section explains that the **stock** spec's `mounts` EPERM under rootless
idmap, and that a devices-only derived spec plus read-only lib binds works. It did not say what
`GroupAdd=keep-groups` does, so a failing `keep-id + keep-groups` row read like a keep-id limitation.

This records the measurement: **keep-groups does not change it — the spec does.** A unit carrying
`GroupAdd=keep-groups` in the SAME keep-id + devices-only-spec + read-only-lib-bind shape starts and
runs, and the EPERM belongs to the spec's `mounts`, not the group flag.
