# 2026.329.2058 — feat(cdi)!: drop require: layer-cuda and the drift control; ship the OpenCL ICD

## Summary

With the toolkit installed **driver-free at the source** (opencharly/layer-cuda#39 at
`v2026.329.1939`; the vdpau arm's fix #42 at `v2026.329.2022`, the tag the build uses), the ordering the `require: layer-cuda` edge existed for is no longer load-bearing:
nothing installs a driver file for this layer's assertion to see.

Deleted: the `require:` edge and its rationale, the `cdi-predicate-drift` control and
`tests/predicate-drift.sh` (the producer's `drv=` twin is gone), and the twin prose in the skill and
the candy comments.

Added: the OpenCL ICD JSON (`/etc/OpenCL/vendors/nvidia.icd` containing `libnvidia-opencl.so.1`),
which `opencl-nvidia` used to provide, with its own build-time assertion; both steps carry ids; the
skill's plan table documents the ICD part.

Changed: **`cdi-no-baked-driver-libs`'s vdpau arm counts the DRIVER file** (`libvdpau_nvidia*`), not
the tree's existence — and the `cdi-layer` skill row now says the same ("the `nvidia` tree, the
vdpau DRIVER file"), and the OpenCL `.icd` is described as an ICD FILE, not a JSON — the generic libvdpau (pulled by `ffmpeg`) ships `libvdpau_trace.so`, so the
form that counted EVERY file in the vdpau tree false-reds a clean image (and the new arm counts the
DRIVER file only, `-maxdepth 1`, where the driver files live). The repo's existing fixture
(`tests/no-baked-driver.sh`) extracts and runs the SHIPPED bodies and is the control for this: its
clean layout creates a `vdpau` DIRECTORY, so the old form reds it (the test would fail) and the new
form passes it.
