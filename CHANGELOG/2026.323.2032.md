# 2026.323.2032 — docs(cdi): the CDI device x userns-mapping wall, measured, and the two legal shapes

## Summary

Two skills gain the one fact a GPU pod with a bind mount cannot work without, measured on the first
pod in the org that had BOTH a CDI device and a host bind (`opencharly/plugin-deploy-pod#81`,
surfaced by the Strata pod extraction, `opencharly/opencharly#1174`).

**`/charly-cdi:cdi` — a new section, "A CDI device and a user-namespace MAPPING are mutually
exclusive":**

- the failing syscall, named by `strace`: `mount_setattr(…, AT_RECURSIVE, MOUNT_ATTR_IDMAP, …) = EPERM`
  — crun applying an **idmapped mount** to the injected CDI mount;
- the mechanism: an idmapped mount needs `CAP_SYS_ADMIN` in the user namespace that owns the
  **filesystem's superblock**, and the CDI sources are host-root-owned files on the host filesystem
  (initial user namespace), which no rootless container can hold. Podman requests the idmap precisely
  because the container carries a userns MAPPING;
- the measured matrix, including the two theories it falsifies: the same failure on TWO images (so not
  the image), and a plain `:idmap` bind failing on **btrfs AND tmpfs** (so not the filesystem — tmpfs
  supports idmapped mounts), plus the "pre-create the CDI target paths in the image" attempt, which
  does not help either;
- the two shapes that DO work: **`--userns=host` with a container-root workload** for a host bind
  (under a rootless pod that uid 0 IS the invoking host user, measured to run the whole stack with
  `--cap-drop ALL --security-opt no-new-privileges`, so the workload needs no capability at all), or a
  **named volume**, where `keep-id` stays correct;
- why there is no third shape, and the three workarounds it rules out (baked driver, pre-created mount
  targets, hand-mounted host libraries — the last is a second implementation of CDI, R2/R3);
- the author-facing consequence: a pod composing this layer with a bind volume must deploy
  `userns=host` + container-root, which `plugin-deploy-pod` now derives from the resolved deploy — so a
  hand `podman run` or a new emitter must apply the same rule.

**`/charly-cdi:cdi-layer` —** the same rule in one line, as a consumer obligation.
