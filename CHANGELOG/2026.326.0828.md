# 2026.326.0828 — feat(cdi): pin layer-cuda v2026.326.0028 and prove the "nothing baked" steps with a fixture

## Summary

`opencharly/layer-cuda#34`, consumer leg. This layer carries the two assertions that catch the failure
it exists for — no host-coupled driver user-space, no `nvidia*` binary is baked — and both assert a
**negative**. Nothing executed them: a predicate widened or narrowed in a later edit reads exactly as
plausible as the correct one, and the producer's own strip had already been falsified once that way
(`libcuda*.so*` deleting `libcudart`).

- **Pin** `layer-cuda` `v2026.323.1604` → `v2026.326.0028`, the release carrying the producer's
  executable strip fixture (layer-cuda#35). The pin comment now names it and states that this
  repo's fixture is the consumer-side twin.
- **`tests/no-baked-driver.sh`** extracts BOTH step bodies from `charly.yml` — their
  `CDI_LIB_DIRS` / `CDI_BIN_DIRS` hooks are the fixture seam — and runs two arms:
  - **clean**: the CUDA runtime (`libcudart`, `libcublas`, a static archive) plus an ordinary
    binary → both assertions PASS. This is the false-positive control: a predicate that reds on the
    runtime fails here.
  - **planted**: `libcuda.so.1`, `libnvidia-ml.so.1`, a `vdpau/libvdpau_nvidia.so.1` twin, the xorg
    `nvidia_drv.so` and `nvidia-smi` → BOTH assertions red, so neither can stop seeing a surface.
