# 2026.331.0355 — docs(cdi): the derived spec's library binds are invisible to a cache-reading consumer

## Summary

Rule 4 of the keep-id CDI contract told a reader to bind the driver libraries read-only to their
SONAME paths — and stopped there. The binds are **invisible to the loader's cache**: the derived
devices-only spec drops the toolkit's `createContainer` hooks, and those hooks are what refreshed
`/etc/ld.so.cache` at container start.

Measured on the same host in the two SHAPES — they are two containers from two images, and the
body says so deliberately: the stock-spec container is the live `qwen3-tts` deployment (image from
2026-11-26T12:28), the derived-spec container is the `qwen3-tts` bed's deploy (image built
2026-11-27T02:25). **The controlled same-image comparison is the pre/post bed run**, not this table:
before the plugin change the same bed on the same image failed synthesis with `libcuda.so cannot
found!`; after it, 16/16 PASS (opencharly/plugin-deploy-pod#104).

| | stock spec (no bind volume → no keep-id)<br>live deploy, image of 11-26 12:28 | derived spec (bind volume → keep-id)<br>bed deploy, image of 11-27 02:25 |
|---|---|---|
| `/etc/ld.so.cache` mtime | **container start** (11-26 12:28:26) | **image build** (11-27 02:25:55) |
| `libcuda` entries | **4** | **0** |
| `/usr/lib/libcuda.so*` | present | **present (bound)** |

What the table establishes is the MECHANISM (a cache from build time cannot know a runtime bind); what
it cannot establish is causality, which is why the bed's before/after pair — same image, same tree —
is pasted below as well.

So a consumer that resolves the driver *through the cache* fails while a direct `dlopen` user still
works — `triton`'s `libcuda_dirs()` reads `ldconfig -p`, falls back to `LD_LIBRARY_PATH`, and with
neither asserts `libcuda.so cannot found!`; the first synthesis is a 500 with the library sitting at
`/usr/lib` (opencharly/plugin-deploy-pod#102).

Refreshing the cache inside the container is **not** available to the image user (`/sbin/ldconfig` →
*Can't create temporary cache file `/etc/ld.so.cache~`: Permission denied*, measured), so the
contract's rule 4 now says the unit must carry the directory itself:
`Environment=LD_LIBRARY_PATH=<the binds' directory>[:<any value the image already set>]`, the derived
directory first.
