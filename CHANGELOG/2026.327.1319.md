# 2026.327.1319 — test(cdi): run the drift control the source comments only promised for the duplicated drv= predicate

## Summary

`cdi-no-baked-driver-libs` carries a **byte-identical copy** of `layer-cuda`'s `drv=` predicate on purpose — a build context cannot reach into another repo's plan — and the comments above it have always claimed *"`diff` of the two blocks is the drift control"*. Nothing ran that diff (opencharly/layer-cuda#34, item 3): change one side and the consumer asserts a set the producer stopped stripping, both sides reading plausible.

This ships that control and wires it:

- **`tests/predicate-drift.sh`** extracts the full `drv=` assignment from BOTH trees (anchored on the assignment, so a comment that merely mentions `drv=` is not mistaken for it) and refuses on a byte difference, naming `DRIFT` and the producer path;
- **`--self-test`** proves it discriminates: identical → PASS, a **one-token** drift → FAIL naming DRIFT, an **absent producer** → a VISIBLE SKIP (never a silent pass);
- **wired as `cdi-predicate-drift`**: the build step runs the self-test first (always discriminating) and then the live comparison, which finds a sibling `layer-cuda` only where **both** trees are materialized; in an image build the live half prints its SKIP lines instead of faking a pass.

## How tested

Both trees taken from the umbrella working set (`charly 2026.327.1010`, `spec v0.2026326.2226`):

```
# the layout that matters — a checkout WITH a sibling layer-cuda (the reviewer's case):
$ /tmp/drift-fix/layer-cdi/tests/predicate-drift.sh --self-test
self-test: OK (identical passes, a one-token drift fails naming DRIFT, an absent producer SKIPs visibly)

$ /tmp/drift-fix/layer-cdi/tests/predicate-drift.sh          # auto-detect path
OK: this layer's `drv=` is byte-identical to the producer's (.../layer-cuda/charly.yml)

$ LAYER_CUDA_DIR=<umbrella>/layer-cuda ./tests/predicate-drift.sh
OK: this layer's `drv=` is byte-identical to the producer's (<umbrella>/layer-cuda/charly.yml)

$ charly box validate
charly box validate: OK — checked 5 candies, 6 distros, 7 builders; 0 warnings, 0 errors
```

Round 1's block 1 was correct: an explicit-but-invalid `LAYER_CUDA_DIR` used to fall through to sibling auto-detect, so in a checkout WITH a sibling the absent-producer arm did a live comparison instead of skipping. An explicit value is now authoritative and never falls back; auto-detect happens only when the variable is unset — and both arms are re-pasted above from the fixed script in exactly that layout.

The wired step executes at build: `charly check box cdi` needs the built image (`charly box pull cdi`), which is the cachyos CDI beds' venue, so the build-time half is not claimed here — it runs the same two commands the pasted output shows.

**Disposable target:** the boxes composing this layer are `distro-cachyos`'s CDI boxes; their beds are the GPU-passthrough ones tracked in opencharly/distro-cachyos#226. No bed is claimed by this PR.
