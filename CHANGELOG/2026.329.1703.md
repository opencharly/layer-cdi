# 2026.329.1703 — fix(cdi): read the injected driver version from NVML, not nvidia-smi

## Summary

The CDI contract's runtime probe ran `nvidia-smi --query-gpu=driver_version`. Under the keep-id
devices-only spec that binary is **not injected** — it is one of the binaries the stock spec's
`mounts` delivered — so the probe failed for the wrong reason in exactly the shape it exists to
certify.

Measured across every GPU image the org deploys:

```
ollama-cdi   python3=/usr/sbin/python3                          nvidia-smi=none
strata       python3=/usr/sbin/python3                          nvidia-smi=none
whisper      python3=/home/user/.pixi/envs/default/bin/python3   nvidia-smi=none
comfyui-cdi  python3=/home/user/.pixi/envs/default/bin/python3   nvidia-smi=none
immich-cdi   python3=/usr/sbin/python3                          nvidia-smi=none
qwen3-tts    python3=/home/user/.pixi/envs/default/bin/python3   nvidia-smi=none
```

The probe now asks **NVML** through python3 and compares that with `/proc/driver/nvidia/version`.
Two manifest claims are corrected in the same file: `pacman -S cuda` pulls `opencl-nvidia` (three
driver files), **not** `nvidia-utils`; and the strip is marked **transitional** — the target is to
install nothing that carries driver user-space. The `require: layer-cuda` comment now records that
the edge is also an ORDERING control and may not be dropped without the box-order replacement.

### Spike

**RCA verdict:** the probe depended on `nvidia-smi`, a binary the derived devices-only spec does not
inject; the missed control was that the check had only ever run in the stock-spec path, so nothing had
executed it in the shape it certifies.

Every plausible candidate was spiked in the keep-id derived-spec container. Commands and raw output:

**A — `nvidia-smi` (the old probe).**
```
$ command -v nvidia-smi || echo absent
absent
```
**FAILS** — the derived spec drops the mounts that delivered it.

**B — NVML through python3 (the winner).**
```
$ python3 -c 'import ctypes;n=ctypes.CDLL("libnvidia-ml.so.1");assert n.nvmlInit_v2()==0;b=ctypes.create_string_buffer(80);n.nvmlSystemGetDriverVersion(b,80);print(b.value.decode())'
615.78.08
```
**WORKS.**

**C — parse the injected versioned filename (`libnvidia-ml.so.<ver>`).**
```
# with the emitter's full bind set (SONAME + versioned path)
$ ls -1 /usr/lib/libnvidia-ml.so.*
/usr/lib/libnvidia-ml.so.1
/usr/lib/libnvidia-ml.so.615.78.08
$ v=$(ls /usr/lib/libnvidia-ml.so.* | grep -v "\.so\.1$" | sed -n 1p); echo "${v##*.}"
08
$ echo "$v" | sed 's/.*\.so\.//'
615.78.08
```
**WORKS only while the emitter binds the versioned path.** With the SONAME bind alone — the S7b
simplification this audit proposes — the versioned name does not exist:
```
$ ls -1 /usr/lib/libnvidia-ml.so.*
/usr/lib/libnvidia-ml.so.1
```
So the probe would be coupled to the emitter's bind-path choice. Not chosen.

**D — `readlink -f` on the SONAME.**
```
$ readlink -f /usr/lib/libnvidia-ml.so.1
/usr/lib/libnvidia-ml.so.1
```
**FAILS to yield a version** — the derived bind places a regular file at the SONAME path, not a
symlink.

**Buffer caveat (why 80 bytes).**
```
$ python3 -c '...; v=ctypes.c_char_p(); n.nvmlSystemGetDriverVersion(ctypes.byref(v),80); ...'
rc=139
```
Segfaults — measured.

**WINNER: B (NVML).** It is the only candidate that asks the library instead of trusting a filename,
and it works in both the full bind set and the SONAME-only shape.
